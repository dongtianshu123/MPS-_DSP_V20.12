## 2. 程序整体框架

这套程序本质上是一个“主循环 + 多中断 + 状态机”的软起动控制系统。

### 2.1 模块职责

`MainCont.c`

- 系统入口
- 完成初始化
- 在主循环中按 `1ms/10ms/100ms` 周期调用各业务函数

`init5011.c`

- 从 EEPROM 读取参数
- 计算起动/保护/自定义曲线相关的派生参数
- 初始化 IO、Timer、CN 等外设

`T1_CTRL.c`

- `T1` 中断产生软件时基
- 实现软起动 `SoftStart()` 和软停 `SoftStop1Ms()/SoftStop2()`

`RelayFlow.c`

- 主状态机
- 管理等待、备妥、起动延时、软起、运行、软停、故障等步骤
- `step11` 是整个系统的核心步骤变量

`Protect1.c`

- 频率检测、相位比对、起动过频保护、过流/欠流/过温/零序等保护逻辑

`ADInterrupt.c`

- ADC 中断
- 采样三相电压/电流/零序/温度
- 做滑动窗口平方和累加，为 RMS 和功率因数计算提供原始量

`Current.c`

- 把 ADC 累积值换算成工程量
- 检测电流上升/下降趋势
- 判断是否满足旁路切换条件

`PhyVol.c`

- 处理过零检测、虚拟过零、触发脉冲定时输出
- `IC4/T4/T5/T2` 共同完成晶闸管触发序列

`IO.c`

- 输入去抖
- 起停/Ready/运行反馈/复位等输入状态形成

`Uart1ModBus.c`

- UART1 Modbus 从站
- 遥控起停、遥调、寄存器映射

`Uart2.c`

- 另一套串口协议，负责参数读写、EEPROM 写入等

## 3. 主执行逻辑

### 3.1 启动流程

入口在 `src/MainCont.c:112`

1. 上电后延时。
2. 调用 `StateInit()` 读取 EEPROM 参数并完成派生量计算。
3. 初始化端口、定时器、ADC、输入捕捉、串口、CN 中断。
4. 进入 `while(1)` 主循环。

### 3.2 主循环节拍

`T1` 中断在 `src/T1_CTRL.c:23` 中设置软件时基：

- `Ms1`
- `Ms5`
- `Ms10`
- `AdMs100`

主循环在 `src/MainCont.c:141-217` 中根据这些标志执行任务。

`100ms` 任务：

- `NoPowerCheck()`
- `StartOFTProtect()`
- `SR_overload()`
- `UnbalanceIProtect()`
- `IORead()`

`10ms` 任务：

- `AdcDescend()`
- `CurrentCheck()`
- `Protect()`
- `RelayFlow()`
- `SoftStart()/SoftStop1Ms()/SoftStop2()`
- `phasecompare()`
- `Frequencydetect1()`
- `Uart2App()`
- `Modbus_Slave_App()`
- `Update_Modbus_Registers()`

### 3.3 状态机主线

核心步骤变量为 `step11`，定义在 `src/RelayFlow.c:26`。

主要状态：

- `0` 等待
- `1` 备妥
- `2` 起动延时
- `3` 软起动
- `4` 运行
- `5` 正常停机
- `7` 故障
- `8` 突跳
- `10/11/12/17/18` 软停相关步骤

主线关系：

1. `step11=0` 且 Ready/无故障/起动间隔允许时进入 `1`
2. 收到起动命令后进入 `2`
3. 起动延时结束且相位比对通过后进入 `3`
4. 在 `3` 中执行软起动算法，同时触发脉冲输出
5. 满足切换条件后进入 `4` 运行
6. 收到停机或故障时进入 `5/7/10/17/18`

### 3.4 触发链路

触发不是在主循环里直接输出，而是由过零和定时器链路完成：

1. `IC4` 捕捉过零，入口 `src/PhyVol.c:210`
2. `zero_cross_processing()` 根据当前运行状态启动 `T5`
3. `T5` 决定导通角延时与脉宽时序
4. `T2` 继续输出 6 脉冲序列

这部分是功率控制的实时核心。

## 4. 主要问题与 BUG

下面按严重程度排序。

### 4.1 严重：Modbus 每 10ms 无条件重写 `StartParams.Data`，会覆盖软起动算法

位置：

- `src/Uart1ModBus.c:384-500`
- `src/MainCont.c:215-216`
- `src/T1_CTRL.c:90-320`

现象：

- `SoftStart()` 会根据起动模式持续调整 `StartParams.Data`
- 但 `Update_Modbus_Registers()` 在每个 `10ms` 周期最后，又根据 `StartParams.AdjustData` 重新计算一次 `StartParams.Data`

问题本质：

- `Update_Modbus_Registers()` 名字看起来只是“刷新寄存器映射”，但它实际修改了主控制量
- 而且这段代码没有判断当前是否处于“远程调试模式”或 `ControlMode==4`

影响：

- 会破坏所有正常软起动模式下的导通角控制
- 只要 `AdjustData` 非零或历史值残留，软起曲线就可能被 Modbus 逻辑抢写
- 这属于控制主线被通信任务干扰的严重设计错误

结论：

- 这是当前代码里最需要优先修复的问题

### 4.2 严重：自定义曲线模式的 `t2/t3/t4` 没有从参数区加载

位置：

- 定义：`h/variable.h:300-304`
- 使用：`src/T1_CTRL.c:263-278`
- 初始化：`src/init5011.c:351-355`
- 二段/三段/四段步长计算：`src/init5011.c:371-382`

现象：

- `ControlMode == 3` 时，`SoftStart()` 依赖 `t1+t2+t3+t4` 进行四段曲线切换
- 但 `StateInit()` 只给 `t1` 和 `t5` 赋值，没有给 `t2/t3/t4` 赋值

影响：

- `t2/t3/t4` 实际值取决于上电后的 RAM 初值或历史残值
- 自定义曲线第二到第四段行为不可预测
- 轻则曲线跳段，重则直接失真或提前结束

结论：

- 这是确定性的功能缺陷，不是“优化项”

### 4.3 严重：Modbus 故障复位命令没有走实际复位通道，故障可能无法解除

位置：

- Modbus 写命令：`src/Uart1ModBus.c:167-172`
- 故障态复位条件：`src/RelayFlow.c:309-320`

现象：

- Modbus 写 `0x0066 = 0x00CC` 时，只做了：
  - `Fault.Byte = 0`
  - `Input.reset = 1`
- 但 `RelayFlow()` 的故障态退出条件是 `Uart2.commandreset==1`

问题本质：

- Modbus 复位设置的标志和状态机真正检查的标志不是同一个
- 同时也没有清除 `ProtectParams.faultflag`

影响：

- 上位机发复位命令后，故障字节可能清了，但状态机仍停在 `step11==7`
- 现场表现就是“看起来复位了，设备其实还锁死在故障态”

### 4.4 严重：软停差值计算分支写错，`StopEnd < StopHead` 时会发生无符号下溢

位置：

- `src/init5011.c:147-153`

代码问题：

- `if` 和 `else` 两个分支都写成了  
  `StartParams.StopDif = StartParams.StopEnd - StartParams.StopHead;`

影响：

- 当 `StopEnd < StopHead` 时，本应得到一个负向减小量
- 但由于变量是无符号型，结果会发生下溢，形成很大的正数
- 接着 `StopStep = StopDif / StopTime`，软停斜率会完全错误

现场风险：

- 软停导通角变化异常
- 可能出现停机过程突变，而不是平滑减小

### 4.5 中高风险：Modbus 3.5T 帧结束判断被写死为固定 10ms，不适配可配置波特率

位置：

- 波特率参数：`src/init5011.c:215-217`
- 帧超时判断：`src/T1_CTRL.c:70-78`

现象：

- 程序支持 EEPROM 参数配置 `modbusbaud`
- 但 `MB.Timer35T > 10` 被固定当作一帧结束条件

影响：

- 对 9600 以外的波特率，帧结束判断都会失真
- 波特率越高，10ms 超时越保守，吞吐下降明显
- 波特率越低，可能在异常抖动时产生错误分帧

结论：

- 既然波特率是可配置的，3.5T 定时也必须跟着计算

### 4.6 中高风险：`0x10` 多寄存器写入没有校验报文长度和字节计数

位置：

- `src/Uart1ModBus.c:196-205`

问题：

- 只检查了 `startAddr + regNum <= MB_REG_MAX`
- 没检查：
  - `MB.RxCnt` 是否足够长
  - `MB.RxBuf[6]` 的字节数是否等于 `regNum*2`

影响：

- 不完整报文或干扰报文仍可能进入写入循环
- 会从未验证的数据区读值，属于通信健壮性缺陷

### 4.7 中风险：中断和主循环共享标志大量未声明为 `volatile`

位置：

- `SysTime` 定义：`src/T1_CTRL.c:21`
- `tSysTime` 声明：`h/variable.h:110-119`
- `zcd_mgr` 声明：`h/variable.h:43-55, 630`
- 主循环读 `SysTime`：`src/MainCont.c:147-208`

问题：

- `SysTime` 由 `T1` 中断写，主循环读
- `zcd_mgr` 的 `signal_quality/use_simulated/simulated_interval` 等在中断和主循环之间共享
- 但这些结构体本身没有声明为 `volatile`

影响：

- 在高优化等级下，编译器可能缓存变量值
- 导致主循环看不到中断刚写入的新状态，或读取时序异常

说明：

- 这类问题现场通常表现为“偶发、难复现、和编译选项相关”

### 4.8 中风险：参数合法性校验里存在多个对无符号变量的无效判断

位置：

- `src/init5011.c:76-79`
- `src/init5011.c:93-96`

问题：

- 例如：
  - `MainParams.SaveParams[3] < 0`
  - `MainParams.SaveParams[4] < 0`
- `SaveParams` 是 `unsigned int`，这些判断永远为假

影响：

- 参数下限保护逻辑不完整
- 代码可读性也会误导后续维护

### 4.9 设计风险：上电后 `while(!RCONbits.BOR);` 可能造成启动卡死

位置：

- `src/MainCont.c:127`

说明：

- 这句代码要求 `BOR` 位置位后才继续执行
- 如果现场复位来源不是 BOR，或者该位语义和当前配置不一致，程序会一直卡在这里

这个问题需要结合芯片复位位定义和实际硬件复位方式再确认，但从软件设计上看风险偏高，不建议保留这种阻塞式等待。

## 5. 流程层面的几个结构性问题

### 5.1 控制主线和通信主线耦合过深

典型例子就是 `Update_Modbus_Registers()` 一边做寄存器镜像，一边修改控制量 `StartParams.Data`。  
这会导致：

- 调试功能污染正常控制逻辑
- 问题定位困难
- 很难保证软起动算法的单一入口

建议：

- 通信层只更新“命令/目标值/参数”
- 控制层只在明确模式下消费这些命令

### 5.2 参数初始化和运行态复位边界不清晰

在 `step11==1` 收到起动命令后又执行 `StateInit()`，意味着每次起动都会重新从 EEPROM 把整套参数装载一遍。  
这会带来两个问题：

- 运行期间被串口暂存到 RAM 的设置可能被重刷
- 调试时很难区分“当前值”到底来自 EEPROM 还是 RAM 修改

### 5.3 状态机步骤号较多，但状态含义分散在多个文件

目前 `step11`、`step3`、`step4`、`step5`、`step6` 同时存在：

- `step11` 管业务状态
- `step3` 管自定义曲线子步骤
- `step4/step5` 管触发时序
- `step6` 管相序检测

这本身不是错，但缺点是：

- 阅读成本高
- 很容易在跨文件修改时引入联动 Bug

---

## 6. 建议的修复优先级

建议先按下面顺序处理：

1. 修 `Update_Modbus_Registers()` 对 `StartParams.Data` 的无条件覆盖
2. 补齐 `ControlMode==3` 下 `t2/t3/t4` 的参数装载
3. 修复 Modbus 故障复位逻辑，统一到状态机实际使用的复位通道
4. 修复 `StopDif` 的符号/方向计算
5. 修复 Modbus 帧长校验和 3.5T 超时算法
6. 给中断共享状态补 `volatile`，并重新检查 ISR/主循环的共享对象
7. 清理无效参数判断和启动阻塞逻辑

---

## 7. 总结

这套程序的总体思路是清楚的，控制链路也比较完整：

- `ADC/过零/触发` 负责实时控制
- `RelayFlow` 负责业务状态机
- `Protect` 负责保护闭锁
- `UART` 负责参数和上位机接口

但当前存在几个很关键的“控制权越界”问题，尤其是：

- Modbus 周期性覆盖导通角
- 自定义曲线参数缺失
- 故障复位链路不闭合
- 软停差值计算错误

这些问题已经不是单纯的代码风格问题，而是会直接影响软起动过程、停机过程和现场联调结果的功能性缺陷。
